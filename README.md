# Trace

**Understand any Python codebase visually. Ask a question, watch an AI agent trace the answer through the code, and learn the codebase one node at a time.**


## The problem

Developers constantly land in code they did not write: a new job, an open-source repo, or code generated by an AI. The usual way to understand it is to grep across dozens of files and hold the call chain in your head. That is slow, and it is easy to get wrong.

## What Trace does

Trace turns a Python repo into an interactive graph, then lets an AI agent answer questions by walking that graph. Every claim the agent makes is checked against the real code before you see it, and the claims that fail are sent back to the model once to fix.

## Main features

- **Any public Python repo:** the Repositories page takes a GitHub URL, clones it, finds where its imports start and builds the graph in seconds. Switch between repos from the breadcrumb.
- **Codebase view:** modules and files as a map of the repo.
- **Click to code:** click any node to open the exact file and line in a code panel.
- **Ask the codebase:** ask "How does a user log in?" and watch the agent trace the answer node by node across the map. Every claim shows whether it was verified, and links to the line that proves it. Edges the parser could not resolve are dashed.
- **Repair:** claims the validator rejects, and gaps in the path, go back to the model for one round of fixes. The answer shows its first draft's tally next to the final one.
- **Agent trace:** a tab in the answer panel with every tool call the agent made, its arguments and results, and the timing of each step, then the answer, the validation and the repair.
- **Graphify:** from the code panel, take one file apart. Its functions become blocks of real code, and arrows run from each calling line to what it calls.
- **Ask about a file or a block:** a question typed on a file's page is about that file. Select a block first and it shows in the ask box, and the agent starts from that function.
- **Recorded questions:** ten answers recorded on the demo repo replay instantly. Anything else runs live.
- **Developer-tool shell:** a ⌘K search, a collapsible sidebar (⌘B), and Auto or Manual playback that steps through an answer one node at a time.

## How it works

```
GitHub URL --> shallow clone
                    |
                    v
Parser (ast + jedi)  -->  Graph (nodes, edges, flagged gaps)        [no AI]
                              |
                              v
   Graph tools  <------  Agent (Muse Spark)
   (search, source,      picks what to read, at most 8 tool calls,
    callers, callees)    answers with a JSON path
                              |
                              v
                  Grounding validator                               [no AI]
                  (every node, edge and quote is checked)
                              |
                              v
                  Repair: rejected claims go back to the model once,
                  and the fixes are validated again
                              |
                              v
        FastAPI (streams every step)  -->  Web UI (React)
```

- **Parser and graph:** deterministic. Python `ast` for structure, `jedi` for name resolution, plus Flask or FastAPI route edges.
- **Agent:** a Meta model in a tool-calling loop over read-only graph tools. It decides what to read next and returns a structured JSON path.
- **Grounding validator:** plain code that rejects any claim that is not in the graph, and any quote that is not in the source.
- **Frontend:** a React and TypeScript single-page app. The map is drawn in Cytoscape.js and the file view in SVG. Its types are generated from the backend's JSON Schema contracts.

## Quickstart

You need [uv](https://docs.astral.sh/uv/) (Python 3.14 is fetched automatically), Node 24 and `make`.

```sh
make setup             # uv sync, npm install
cp .env.example .env   # add META_API_KEY

make dev-api           # FastAPI on http://localhost:8000, serving the mock data
make dev-api-real      # the same, serving the demo repo (needs the clone under Attribution)
make dev-web           # Vite on http://localhost:5173, proxies /api to the API

make test              # pytest
make lint              # ruff, oxlint
make build-web         # builds web/dist, which the API serves at /
make schemas           # re-export docs/contracts after changing a contract
```

Open http://localhost:8000 after `make build-web`, or the Vite URL while developing. Repos added from the Repositories page are stored in `data/repos/`, which is gitignored. Adding one needs `git` on the PATH; it takes public GitHub repos of up to 1,500 Python files, one at a time.
