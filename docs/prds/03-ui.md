# UI

> Status: built on the mock data, 2026-10-31. Scope is UI priorities 1–3 plus the code panel. Learning-mode UI (fog, tap-checks, progress)
> is specified in `04-learning-mode.md`. Product background is in `.claude/idea-product.md`.

## Goal

Make the agent's walk through the call graph legible and trustworthy. A viewer should be able to ask a question, watch
the path light up step by step, and see at a glance which claims the graph backs and which it does not. Everything else
in the UI serves that.

**Non-goals** (explicit cuts from the product spec): PR diff mode, other languages, accounts, loading arbitrary repos,
WebGL or Three.js, React Flow, any database, auth, Next.js. No light theme.

## Current state

When this PRD was written, the workspace was a default light shadcn page: a Cytoscape graph with flat colours, one
hard-coded question button and a raw JSON event log. The landing page was already dark (#090a0f) with a helix animation,
so the app did not match it.

## Aesthetic direction: space factory

Revised 2026-10-31 after a first look: the map was hard to read for someone who doesn't know the code. The map is now a
flat 2D factory floor in space. Each module is a dark plate with a coloured tab and a one-line caption, nodes are small
label cards on their plate, call links are thick belts, and the answer is an orange parcel that rides them. Colour means
module. Connections that only describe wiring (imports, injects, inherits, implements) are hidden until asked for.

The original direction is kept below for reference.

### Original direction: observatory at night

A dark star chart. Modules are soft nebula regions, functions and classes are stars, the agent's path is a bright thread
drawn across them. The landing page already sets the mood; the workspace continues it.

- **Palette.** Near-black background (#090a0f, matching the landing page) with a faint starfield. Node-type colours become
  named CSS variables in `web/src/index.css`, replacing the hex map `NODE_COLORS` in `GraphView.tsx`. The neutral shadcn
  `:root` tokens are replaced and dark becomes the only theme.
- **Glow is for agent state.** Idle nodes are dim and small. Only nodes the agent has visited, or the one under the
  cursor, glow. This is what makes the animation readable.
- **Type.** Inter is dropped. A display serif for headings and the agent's explanations (proposed: Instrument Serif via
  `@fontsource`), JetBrains Mono for node labels, code, claim chips and chrome.
- **Claim status is never colour alone.** `verified` = solid filled check, `unverified` = hollow marker plus "unverified"
  label, `gap` = broken-line marker plus "gap" label. All three also differ in colour.
- **Motion.** One orchestrated moment (the path animation) rather than many micro-effects. `prefers-reduced-motion`
  replaces camera moves and glow pulses with instant state changes.

## Layout

Full-bleed map. Over it:

- **Ask bar** along the bottom: free-text input, submit, and the demo question as a suggested chip. Disabled while a run
  is in progress.
- **Right column** (slides in on the first run): the agent narration, one card per path step. The column replaces the
  fixed aside.
- **Code panel**: opens over the right column when a node is opened, closes with Escape or a close button.
- **Top-left**: repo name and commit short SHA from `Graph.repo` and `Graph.commit_sha`. Top-right: the command palette
  hint (`/` or Cmd+K).

Minimum supported width is 1280px. Mobile is out of scope.

## Node and edge visual states

| State | Trigger | Look |
|---|---|---|
| Default | — | Small, dim, type colour at low opacity; label shown only for modules and at higher zoom |
| Hovered | Pointer over node | Brighter, label shown |
| Selected | `selectedNode` | Ring plus label, code panel opens |
| Visited by agent | `node_visited` event | Glow and label, stays lit for the rest of the run |
| Current step | Active step during playback | Pulse, camera centred |
| Unverified | Step whose claims include `unverified` | Hollow ring marker |
| Gap | Step whose claims include `gap`, or edge between steps with no real edge | Dashed thread segment |
| Uncertain edge | `edge.type = "uncertain"` | Dashed, distinct colour |

Fog and understood states are named in the store (`NodeState`) but defined in `04-learning-mode.md`. They must compose
with the states above.

## Requirements

### P1. Question to path animation

- The viewer types a question and submits. The UI calls `streamAsk` and consumes `AgentEvent`s as they arrive.
- `tool_call` and `tool_result` events show in a quiet trace line ("search_nodes: login … 2 matches"). They are not the
  main content.
- `node_visited` lights the node and moves the camera to it. Steps advance at about 400ms each; if events arrive faster
  than that, they are queued and played at that pace.
- `final_path` renders one narration card per step: the node name, the `explanation`, and a chip per claim with its
  status. A claim with a `quote` shows it on expand.
- Clicking a card centres its node; clicking a node in the path scrolls to its card.
- An `error` event shows an inline message and leaves the partial path visible. Asking again clears the previous run.

Acceptance, against `data/mock/events.jsonl` (12 events, 3 `node_visited`, 4 path steps):
1. The three visited nodes light in event order, with a camera move to each.
2. The final path shows its 4 steps. The mock has one `unverified` claim (on `UserService.authenticate`) and one `gap`
   claim (on `hash_password`); both are visibly different from the verified ones without relying on colour. The
   `hash_password` step is in the path but was never in a `node_visited` event, so the UI must light it from
   `final_path`, not only from visits.
3. Re-asking resets all lit nodes and cards.
4. Free-text input submits (the mock API ignores the text until `/api/ask` is wired to the real loop).

### P2. Codebase to file view

- Double-clicking a module, or opening it from the palette, zooms the camera into that module and shows its functions and
  classes as the active layer. Escape (or a breadcrumb in the top-left) zooms back out.
- The transition is a continuous camera zoom plus a fade of the out-of-focus modules, not a hard swap.
- The agent path stays visible in file view for nodes inside that module.

Acceptance: from the full map, zooming into `taskboard.services.users` (8 nodes) and back out takes under a second each
way, and the previously selected node is still selected afterwards.

Open: methods as separate stars or inside their class (carried over from the product spec). Default for the first build:
methods as stars, grouped under a faint class outline.

### P3. Command palette

- `/` or Cmd+K opens a palette (`cmdk`). Fuzzy search (`fuse.js`) runs over `graph.nodes` by name, id and docstring.
- Each result shows the node type, name and module. Enter selects the node and centres the camera on it; if the node is in
  a different module, it zooms there first (P2).
- Escape closes. The shortcut does not fire while typing in the ask bar.

Acceptance: typing "auth" lists the `authenticate` method and the `auth` module; selecting one centres and selects it.

### Code panel

- Opens on node select and on clicking a claim chip. Shows the node's file with Shiki highlighting, scrolled to
  `line_start`, with `line_start`–`line_end` marked.
- When opened from a claim with a `quote`, the quoted line is highlighted.
- Shows file path, line range and the node's docstring above the code.

Dependency: source text has no runtime source yet (`.claude/Project_Context/status.md`, open question 1). Build against
`GET /api/source` as proposed there. The mock fixtures hold no source text, so until that route exists a hand-written
stub file for the `taskboard` login nodes is needed to test the panel; the panel must show a clear "source unavailable" state, never an empty box.

## Data and state

Reads from the contracts: `Graph` (nodes with `x`, `y`, `module`, `file`, `line_start`, `line_end`, `docstring`; edges
with `type` and `resolved`), `AgentEvent`, and `Claim.status`. No new contract fields are required.

Existing store (`web/src/store.ts`): `selectedNode`, `agentRun`, `learningMode`, `nodeStates`. New state this PRD adds:

- `playback`: current step index and whether playback is running, so animation can lag behind the event stream.
- `view`: `{ level: 'codebase' | 'file', module: string | null }`.
- `paletteOpen` and `codePanel` (open node id and optional highlighted quote).

Layout positions come from the baked `x`, `y` in `graph.json`. No live layout runs.

## Cut order

If time runs short, cut from the bottom:

1. Hover cards on nodes (signature and docstring). Not specified here; the node state table already covers hover.
2. Small celebration when a module is fully understood. Depends on learning mode.
3. File-view detail: ship the zoom, drop class outlines and in-module path display.
4. Starfield and glow polish. Keep the dark palette and type.

P1 is never cut. The grounding validator's output is the product's differentiator and P1 is where it is visible.

## Open questions

1. **Display font.** Instrument Serif is a proposal. Confirm after seeing it next to the landing page.
2. **Gap meaning.** The UI renders `gap` as a dashed segment, but the contract and the architecture doc define it
   differently (status.md, question 4). The look is the same either way; the label text depends on the answer.
3. **Source text.** `GET /api/source` serves `TRACE_SOURCE_DIR`, which defaults to the stubs in `data/mock/source/`. Point
   it at the pinned clone for the real repo (status.md, question 1).
4. **Landing page.** Keep the helix animation as is, or tie it to the workspace palette. Default: keep.
5. **Node granularity in file view.** See P2.
